### 📸 FLOW 1: PHOTO UPLOAD → LOOKS GENERATION → DATABASE STORAGE → RETRIEVAL

#### **Step 1: Upload Photo & Create Avatar**

**Endpoint:** `POST /api/photo-avatars/create-with-looks`

**What Happens:**
1. Client uploads image file (JPEG/PNG/WebP, max 50MB)
2. Backend receives the file via multer middleware
3. Image is uploaded to HeyGen's CDN: `POST https://upload.heygen.com/v1/asset`
4. HeyGen returns an `image_key` (e.g., `image/abc123/original`)
5. Backend creates avatar group: `POST /v2/photo_avatar/avatar_group/create`
6. HeyGen returns a `group_id` (e.g., `5b5566c8bba64376b154abdb565e0333`)
7. **API returns immediately** with `group_id` and status `"processing"`

**Response (Immediate ~2 seconds):**
```json
{
  "success": true,
  "group_id": "5b5566c8bba64376b154abdb565e0333",
  "status": "processing",
  "message": "Avatar created. Training and look generation will complete in ~6-8 minutes."
}
```

#### **Step 2: Background Processing (Fire-and-Forget)**

The backend **immediately** triggers a background workflow via self-HTTP-call to `/api/photo-avatars/background-process`:

**Timeline:**
1. **Wait 30 seconds** - HeyGen processes the uploaded image
2. **Start Training** - `POST /v2/photo_avatar/train` with `group_id`
3. **Poll Training Status** - Every 5 seconds check `GET /v2/photo_avatar/train/status/{group_id}`
4. **Training Complete** - Status changes from `"processing"` → `"ready"` (takes 2-5 minutes)
5. **Generate 4 Looks** - Make 4 parallel calls to `POST /v2/photo_avatar/look/generate`
6. **Poll Look Generation** - Check each `generation_id` until status is `"success"`
7. **Save to Database** - Each completed look is saved via `storage.upsertGalleryItemBySource()`

**Total Time:** ~6-8 minutes for all 4 looks to be ready

#### **Step 3: Database Storage**

Each generated look is stored in the `gallery_items` table:

**Table:** `heygen_app.gallery_items`

**Schema:**
```typescript
{
  id: number;              // Auto-increment primary key
  userId: number | null;   // Null for anonymous workflows
  sessionId: string;       // "automated-workflow" for API calls
  mediaType: string;       // "look"
  sourceType: string;      // "look_generation"
  sourceId: string;        // "{generation_id}:{index}"
  previewUrl: string;      // HeyGen CDN URL for the look image
  title: string;           // "Avatar Name Look #1"
  status: string;          // "ready"
  metadata: {
    generationId: string;  // HeyGen generation ID
    groupId: string;       // Avatar group ID
    lookIndex: number;     // 0, 1, 2, 3
    prompt: string;        // Look generation prompt
    avatarName: string;    // Avatar name
  }
  createdAt: Date;
  updatedAt: Date;
}
```

**Storage Method:**
```typescript
await storage.upsertGalleryItemBySource({
  userId: null,
  sessionId: 'automated-workflow',
  mediaType: 'look',
  sourceType: 'look_generation',
  sourceId: `${generationId}:${index}`,
  previewUrl: lookImageUrl,
  title: `${avatarName} Look #${index + 1}`,
  status: 'ready',
  metadata: {
    generationId,
    groupId,
    lookIndex: index,
    prompt: lookPrompts[index],
    avatarName
  }
});
```

**Database Operation:** Uses `INSERT ... ON CONFLICT DO UPDATE` to prevent duplicates

#### **Step 4: Retrieving Looks from Database**

**Endpoint:** `GET /api/photo-avatars/status/:groupId`

**What Happens:**
1. Backend calls `storage.getGalleryItems('automated-workflow', undefined, 'look')`
2. SQL Query:
```sql
SELECT * FROM heygen_app.gallery_items
WHERE session_id = 'automated-workflow'
  AND media_type = 'look'
ORDER BY created_at DESC;
```
3. Filter results by `metadata.groupId` to match the requested avatar
4. Return looks array with `image_url`, `generation_id`, `prompt`, etc.

**Response:**
```json
{
  "groupId": "5b5566c8bba64376b154abdb565e0333",
  "training": {
    "status": "ready"
  },
  "looksCount": 4,
  "looks": [
    {
      "id": "gen123:0",
      "name": "John Doe Look #1",
      "image_url": "https://files2.heygen.ai/...",
      "status": "ready",
      "generation_id": "gen123",
      "prompt": "professional business attire, confident smile"
    },
    ...
  ]
}
```

**Frontend Retrieval:**
- Frontend poll `GET /api/photo-avatars/status/{groupId}` every 30 seconds
- When `looksCount > 0`, display the looks
- User can select a look for video generation

### 🎬 FLOW 2: USING LOOKS TO GENERATE VIDEOS

There are **3 ways** to generate videos with avatars:

#### **Option A: Avatar IV (Direct Photo → Video)**

**Endpoint:** `POST /api/heygen/videos`

**What Happens:**
1. Client uploads photo directly or uses existing `image_key`
2. Backend calls HeyGen: `POST /v2/video/av4/generate`
3. Payload includes:
```json
{
  "image_key": "image/abc123/original",
  "script": "Hello, welcome to our platform!",
  "voice_id": "1c7c897eeb2d4b5fb17d3c6c70250b24",
  "video_orientation": "landscape"
}
```
4. HeyGen returns `video_id` immediately
5. Video generation happens in background (2-5 min)
6. Poll `GET /api/heygen/videos/{video_id}` until status is `"completed"`

**Storage:**
- Creates `video_generations` record with `request_id`, `avatar_id`, `script_text`
- Creates `gallery_items` record with `mediaType: "video"`, `sourceType: "video_generation"`

#### **Option B: Motion Video (Trained Avatar + Look + Motion)**

**Endpoint:** `POST /api/heygen/videos/motion`

**What Happens:**
1. Client provides:
   - `groupId` - Trained avatar group
   - `lookId` - Selected look from generated looks
   - `motionId` - Motion style ID (from HeyGen motion list)
   - `script` - Text to speak
   - `voiceId` - Voice selection
2. Backend calls HeyGen: `POST /v1/video/generate`
3. Payload:
```json
{
  "video_type": "motion",
  "group_id": "5b5566c8bba64376b154abdb565e0333",
  "look_id": "look_abc123",
  "motion_id": "motion_xyz789",
  "audio": {
    "type": "text",
    "text": "Hello!",
    "voice_id": "voice123"
  },
  "ratio": "16:9"
}
```
4. Video generates with **realistic hand gestures and body movement**
5. Poll status until complete

**Requirements:**
- Avatar must be trained (`training.status === "ready"`)
- Need at least 1 generated look
- Need to select a motion style

#### **Option C: Avatar Library (Reuse Existing Avatars)**

**Endpoint:** `GET /api/avatars/library`

**What Happens:**
1. Backend retrieves:
   - Trained avatars from `avatars` table
   - Generated looks from `gallery_items` table where `mediaType = "look"`
2. Combines both into unified library:
```typescript
const looksAsAvatars = generatedLooks.map(look => ({
  id: look.id,
  heygenAvatarId: `look_${look.sourceId}`,
  avatarName: look.title,
  imageUrl: look.previewUrl,
  avatarGroupId: look.metadata?.groupId,
  isGeneratedLook: true,
  hasMotion: false
}));

const allItems = [...validAvatars, ...looksAsAvatars];
```
3. Frontend displays unified avatar library
4. User selects avatar/look for video generation

### 🗄️ DATABASE SCHEMA OVERVIEW

#### **Table 1: `avatars`**
Stores trained avatar metadata
```sql
CREATE TABLE avatars (
  id SERIAL PRIMARY KEY,
  heygen_avatar_id VARCHAR(255) UNIQUE,
  avatar_group_id VARCHAR(255),
  avatar_name VARCHAR(255),
  image_url TEXT,
  image_key VARCHAR(255),
  is_trained BOOLEAN DEFAULT false,
  has_motion BOOLEAN DEFAULT false,
  session_id VARCHAR(255),
  user_id INTEGER REFERENCES users(id)
);
```

#### **Table 2: `gallery_items`**
Stores looks, videos, and other media
```sql
CREATE TABLE gallery_items (
  id SERIAL PRIMARY KEY,
  user_id INTEGER REFERENCES users(id),
  session_id VARCHAR(255),
  media_type VARCHAR(50), -- "look", "video", "image"
  source_type VARCHAR(50), -- "look_generation", "video_generation"
  source_id VARCHAR(255), -- Unique identifier from HeyGen
  preview_url TEXT,
  title VARCHAR(255),
  status VARCHAR(50), -- "ready", "processing", "failed"
  metadata JSONB, -- Flexible storage for any extra data
  created_at TIMESTAMP DEFAULT NOW(),
  UNIQUE(source_type, source_id) -- Prevent duplicates
);
```

#### **Table 3: `video_generations`**
Tracks all video generation requests
```sql
CREATE TABLE video_generations (
  id SERIAL PRIMARY KEY,
  session_id VARCHAR(255),
  user_id INTEGER REFERENCES users(id),
  request_id VARCHAR(255) UNIQUE, -- HeyGen video_id
  avatar_id INTEGER REFERENCES avatars(id),
  script_text TEXT,
  video_url TEXT,
  duration INTEGER, -- Estimated duration in seconds
  created_at TIMESTAMP DEFAULT NOW()
);
```

## API 1: Create Avatar with Looks

**Endpoint:** `POST /api/photo-avatars/create-with-looks`

Upload an image and automatically get a trained avatar with 4 professional looks.

### Request

```bash
curl --request POST \
  --url http://gb-video-studio-env-2.eba-h2pwbutp.us-east-2.elasticbeanstalk.com/api/photo-avatars/create-with-looks \
  --form 'image=@/path/to/photo.jpg' \
  --form 'name=John Doe' \
  --form 'prompt=professional business attire, confident smile' \
  --form 'orientation=square' \
  --form 'pose=half_body' \
  --form 'style=Realistic'
```

### Parameters

- `image` (required): Image file (JPEG, PNG, WebP)
- `name` (optional): Avatar name (default: "Avatar {timestamp}")
- `prompt` (optional): Base look description. If omitted, the server will use safe default prompts for the 4 generated looks.
- `orientation` (optional): "square", "horizontal", or "vertical" (default: "square")
- `pose` (optional): "half_body", "close_up", or "full_body" (default: "half_body")
- `style` (optional): "Realistic", "Pixar", "Cinematic", etc. (default: "Realistic")

### Response (Immediate)

**The API returns immediately** - processing happens in background.

```json
{
  "success": true,
  "group_id": "5b5566c8bba64376b154abdb565e0333",
  "avatar_name": "John Doe",
  "status": "processing",
  "message": "Avatar created. Training and look generation will complete in ~6-8 minutes.",
  "check_status_url": "/api/photo-avatars/status/5b5566c8bba64376b154abdb565e0333",
  "estimated_completion": "2025-12-12T23:05:00.000Z"
}
```

### Notes on Look Generation

Internally, this workflow calls HeyGen's look generation API:

- `POST https://api.heygen.com/v2/photo_avatar/look/generate`
- HeyGen requires both `group_id` and `prompt` for each look generation request.

If you want to call HeyGen directly (for debugging), the minimal valid payload looks like:

```bash
curl --request POST \
  --url https://api.heygen.com/v2/photo_avatar/look/generate \
  --header 'accept: application/json' \
  --header 'content-type: application/json' \
  --header 'x-api-key: <your-api-key>' \
  --data '{
    "group_id": "<avatar-group-id>",
```

## Notes

2. **File size limit:** 50MB max
3. **Supported formats:** JPEG, PNG, WebP, GIF

5. **Polling recommended:** Check status every 30 seconds using the provided `check_status_url`
6. **Concurrent requests:** Safe to make multiple requests - each gets a unique `group_id`
7. **No timeouts:** The API returns quickly, background processing can take 6-13 minutes

## Complete Workflow Example

### Scenario 1: Avatar with Looks Only

```bash
# Step 1: Create avatar with looks (returns immediately)

  -F "name=John Smith"

# Response (immediate, ~2 seconds):
# {"group_id": "abc123", "status": "processing", "estimated_completion": "2025-12-12T23:05:00Z"}

# Step 2: Poll status every 30 seconds
curl http://gb-video-studio-env-2.eba-h2pwbutp.us-east-2.elasticbeanstalk.com/api/photo-avatars/status/abc123

# Response while processing:
# {"workflow_status": {"percent_complete": 45, "ready_for_looks": false}}

# Response when complete (after ~6-8 minutes):
# {"workflow_status": {"percent_complete": 100, "ready_for_looks": true}, "looks": {"count": 4, ...}}
```

```bash
# Step 1: Generate video from image (returns immediately)
```
